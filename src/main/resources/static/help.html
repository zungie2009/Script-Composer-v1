LLM Script Composer

Create a clear software specification through a guided questionnaire, download it, and give it to the implementation model of your choice.

Works completely offline

The Composer is a standalone plain Java web application. Creating projects, answering questionnaires, generating and downloading scripts, reviewing revisions, and recording experiments require no Internet connection.

The Composer does not contact an LLM or send your project information to an external service. You need an Internet connection only when you independently submit a downloaded script to an online model.

1. Start a project

  1. Open Projects and select New project.
  2. Enter a recognizable project name.
  3. Search or browse the preset catalog.
  4. Choose an application preset for a complete business application, or a UI preset when you only need an interface specification.

Clicking an existing project card resumes its questionnaire. The card’s Tracker button opens its model experiments, while Delete removes the project and its complete local history.

2. Complete the questionnaire

Each page asks one focused question. Select the choices that describe the application you actually want, then use Next. The progress rail lets you return to completed steps.

  • Choose all records and workflows the finished application must support.
  • Use business terms consistently. Select a customer, work item, resource, appointment, inventory item, or other record only when it belongs in the application.
  • If you change an earlier answer, review the later steps again because choices that depended on the old answer may be cleared.
  • Your current stage is saved with the project, and major stages have stable browser URLs.

3. Review before generating

The Review page shows the complete set of answers. Select any row to correct it. Confirm that the selected records can support the selected workflows—for example, scheduling normally needs an appointment, job, event, or schedulable resource.

Select the target profile only after the requirements are correct. Changing the target changes how instructions are presented to the model; it does not change the application you requested.

4. Choose a target model

Portable
Use when you want a model-neutral script or plan to compare several models.
ChatGPT
Uses delivery guidance suitable for a ChatGPT implementation session.
Claude
Uses delivery guidance suitable for a Claude implementation session.
Gemini
Provides additional explicit implementation guidance because testing showed that Gemini benefits from more detail.
DeepSeek
Experimental. September 2026 testing did not reliably produce the requested standalone browser application. Stop after one failed architectural correction and try a different model.

5. Generate and download

  1. Select Generate compressed Script.
  2. Open Revisions.
  3. Download the generated JSONC file for the revision you want to test.
  4. Keep the downloaded revision unchanged so results from different models remain comparable.

The Composer checks the specification before making it available. If generation is blocked, return to the questionnaire and add the record, relationship, or workflow information identified by the error.

6. Send the script to an LLM

Start a fresh model conversation, attach the downloaded JSONC file, and give a short delivery request. Do not rewrite the script into a long prompt.

Example request
Build the complete runnable application described by the attached script. Follow every requirement and acceptance condition. Return the source code, startup instructions, tests, and a summary of any specification conflict you find.

Ask the model to report conflicts instead of silently inventing missing entities or changing business rules. Before accepting the result, run the application, exercise its visible workflows, restart it to verify persistence, and reproduce its automated tests.

7. Compare results in the Tracker

The Experiment Tracker records which revision and model you tested, whether the result succeeded, your rating, and important findings. Use a separate entry for each model or retry so you can distinguish a script improvement from a model-specific result.

Useful findings include generation time, missing pages, incorrect entities, dead controls, persistence failures, test results, corrections required, and whether the delivered project opened cleanly in your development environment.

Saving work and backups

File storage is the default and needs no database driver. Projects, revisions, and experiments are saved under the configured local data directory. Back up that directory when the history matters.

Database storage uses JDBC and is intended for developers who prefer a database-backed repository. Configure the connection in composer.properties and ensure the selected JDBC driver is available at runtime.

Downloaded JSONC files are independent copies. Deleting a project from the Composer does not remove files you already downloaded elsewhere.

Run in STS or Eclipse

  1. Select File > Import > Existing Maven Projects.
  2. Choose the folder containing pom.xml and finish the import.
  3. Open org.roberttu.llmscriptcomposer.LlmScriptComposerApplication.
  4. Select Run As > Java Application.
  5. Open http://127.0.0.1:8090.

The same class is the entry point used by the executable JAR.

Troubleshooting

The application does not start
Confirm Java 21 is installed and that the configured port is not already in use.
A project does not appear
Confirm the application is using the same storage mode and data directory as the previous run.
Generation is blocked
Read the displayed validation message, return to the questionnaire, and correct the incompatible or missing selection.
The LLM builds a console program
Use the correct target profile, start a fresh conversation, attach the script itself, and explicitly request the complete runnable browser application described by it.
The model reports a conflict
Record it in the Tracker. Correct the preset or questionnaire metadata rather than repeatedly asking the model to guess.
